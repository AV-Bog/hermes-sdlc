# hermes-sdlc

Плагин для Hermes Agent, который ведёт агента по этапам разработки: этап меняется, когда
появляется артефакт нужного вида, а действие, несовместимое с этапом, блокируется до
исполнения.

## Зачем

Агент пишет код по одному запросу и объявляет готово; дефекты находит человек. Плагин должен
проверить, меняет ли принуждение качество результата, а не только порядок действий. Качество
считает внешний судья, не агент.

## Как работает

- этап не хранится счётчиком, а выводится из файлов проекта: `design → code`. Вход в
  `code` - `design.md` с обязательными разделами и списком файлов от корня проекта;
- перед вызовом инструмента плагин проверяет, совместимо ли действие с этапом, и может
  вернуть `{"action": "block"}` с текстом отказа;
- права выданы закрытым списком инструментов на этап: всё, чего в списке нет, блокируется,
  поэтому обход через `browser_exec` или новый инструмент Hermes закрыт ([docs/decisions.md, §4](docs/decisions.md#права-по-этапам));
- режим `advisory` считает и напоминает, но не блокирует - так принуждение сравнивается с
  напоминанием.

Чего ещё нет: защита файлов по хешам и автоматический вход в `verify` (M2), `state.json` и
отчёт (M3).

## Что в репозитории

| Путь | Что |
|---|---|
| `docs/decisions.md` | устройство: хуки, этапы, права, состояние, защита, что не решено, порядок работ |
| `plugin/hermes-sdlc/` | плагин: этап по файлам проекта, права белым списком, блокировка, режим `advisory` |
| `plugin/hermes-sdlc/SKILL.md` | скил `sdlc-stages`: порядок работы - задача → архитектура → код → проверка; текст один на плечи `skill`, `advisory`, `enforce` |
| `tests/` | тесты плагина: корень, разбор `design.md`, права, регистрация хуков (`python3 -m unittest discover -s tests -t tests`) |
| `bench/` | песочница и замер: плечи, изоляция, судья |
| `bench/tasks/notes-categories/` | задача: заметки с категориями; исходные тесты в `seed/`, контракт новых команд в `TASK.md` |
| `bench/tasks/job-queue/` | задача: очередь задач по HTTP с нуля |
| `bench/spike/` | одноразовый плагин-пробник и сценарии спайка M0 |

## Статус

M1 готов и проверен живыми прогонами 11 ноября 2026. Плагин в `plugin/hermes-sdlc/`: этап по
файлам проекта, права закрытым списком инструментов на этап, блокировка с текстом отказа, режим
`advisory`, отметка о загрузке. 44 теста плагина зелёные, `hermes plugins doctor` подтверждает
импорт и регистрацию четырёх хуков.

Четыре плеча на одной задаче (`job-queue`, по одному прогону):

| Плечо | Судья | Вызовы | Цена | `design.md` |
|---|---|---|---|---|
| `off` | 14 из 14 | 8 | $0.0061 | нет |
| `skill` | 14 из 14 | 23 | $0.0170 | 4,1 КБ |
| `advisory` | 14 из 14 | 24 | $0.0193 | 7,3 КБ |
| `enforce` | 14 из 14 | 33 | $0.0319 | 8,7 КБ |

Качество на этой задаче плечи не различает: все четыре решения прошли судью полностью.
Различается цена и наличие плана. По одному прогону на плечо, поэтому разница - гипотеза, а не
результат; разбор в [docs/decisions.md, §16](docs/decisions.md#m1-результаты-первого-прогона).

Прогон `enforce` на ловушке `job-queue`: агент получил блок на `terminal` и два блока на запись
кода, оформил `design.md` и решил задачу.

Спайк M0 проведён 9 ноября 2026: блокировка из `pre_tool_call` работает в `-z` и в субагенте,
`pre_verify` с ответом `continue` продлевает работу, `--yolo` хуки не снимает. Обход через
`browser_exec` закрыт белым списком инструментов; подробности в
[docs/decisions.md, §15](docs/decisions.md#спайк-m0-результаты-первого-прогона).

Следующий этап - M2: хеши защищённых файлов, сверка после вызова, откат, счётчик нарушений и
вход в `verify` по сверке объявленных файлов с диском.
