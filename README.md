# hermes-sdlc

Плагин для Hermes Agent, который ведёт агента по этапам разработки: этап меняется, когда
появляется артефакт нужного вида, а действие, несовместимое с этапом, блокируется до
исполнения.

## Зачем

Агент пишет код по одному запросу и объявляет готово; дефекты находит человек. Плагин должен
проверить, меняет ли принуждение качество результата, а не только порядок действий. Качество
считает внешний судья, не агент.

## Как работает

Ниже - целевое устройство; из перечисленного сейчас работает только механизм хуков в спайке
(`bench/spike/`), а сам плагин ещё не написан (см. «Статус»).

- этап не хранится счётчиком, а выводится из файлов проекта: `design → code → verify`. Вход в
  `verify` - по объявленному: когда все файлы из списка в `design.md` уже есть на диске;
- перед вызовом инструмента плагин проверяет, совместимо ли действие с этапом, и может
  вернуть `{"action": "block"}`;
- защищённые файлы (тесты, артефакты этапа) сверяются по хешам: подмена откатывается и
  считается нарушением;
- режим `advisory` делает то же, но не блокирует - так принуждение сравнивается с напоминанием.

## Что в репозитории

| Путь | Что |
|---|---|
| `docs/decisions.md` | устройство: хуки, этапы, права, состояние, защита, что не решено, порядок работ |
| `plugin/hermes-sdlc/SKILL.md` | скил `sdlc-stages`: порядок работы - задача → архитектура → код → проверка; текст один на плечи `skill`, `advisory`, `enforce` |
| `bench/` | песочница и замер: плечи, изоляция, судья |
| `bench/tasks/notes-categories/` | задача: заметки с категориями; исходные тесты в `seed/`, контракт новых команд в `TASK.md` |
| `bench/tasks/job-queue/` | задача: очередь задач по HTTP с нуля |
| `bench/spike/` | одноразовый плагин-пробник и сценарии спайка M0 |

## Статус

Плагин не написан. Спайк M0 проведён 9 ноября 2026: блокировка из `pre_tool_call` работает в
`-z` и в субагенте, `pre_verify` с ответом `continue` продлевает работу, `--yolo` хуки не
снимает. Обход через `browser_exec` закрыт белым списком инструментов; подробности в
[docs/decisions.md, §15](docs/decisions.md#спайк-m0-результаты-первого-прогона). В репозитории
есть текст напоминания, плечо `skill` в стенде и две задачи. Следующий этап - M1: скелет
плагина, резолв корня, `detect_stage` на два этапа, `block`, режим `advisory`.
