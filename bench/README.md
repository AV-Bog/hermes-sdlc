# Стенд: песочница и замер

Эксперимент: задачи, четыре плеча, внешний судья. В поставку плагина не входит - в пакет идёт
только `plugin/`.

Задач две:

| Задача | Начало | Что проверяет судья |
|---|---|---|
| `notes-categories` | готовый проект с тестами | исходные тесты из `seed/`, чтение старого файла, контракт новых команд |
| `job-queue` | каталог без кода | сервис по HTTP: приём без ожидания, результат, 4xx вместо 5xx, 20 параллельных задач |

`notes-categories` - случай «доработай, не сломав». `job-queue` - «сделай приложение» с нуля;
он же площадка для спайка M0: первое осмысленное действие в пустом каталоге - запись кода, то
есть самый прямой случай проверить блокировку записи до плана.

## Устройство

```
bench/
├── run.py                  # один прогон: дом + песочница + агент + вердикт
├── tasks/<задача>/
│   ├── TASK.md             # промпт, который видит агент
│   ├── seed/               # изначальное состояние проекта; тесты из него же берёт судья
│   │                       # (.gitkeep держит каталог в git: у job-queue он пуст)
│   └── grader.py           # внешний судья (в гитигноре)
├── spike/                  # спайк M0: плагин-пробник и сценарии проверки хуков
│   ├── sdlc-spike/         # одноразовый плагин: журнал хуков, блокировка по чёрному и белому списку
│   └── run.py              # сценарий = прогон `hermes -z` с плагином
├── home-template/          # заготовка HERMES_HOME
│   └── config.yaml.tmpl     # сюда подставляются режим и список плагинов
└── runs/                   # результаты прогонов (в git не попадает)
```

Спайк M0 (`bench/spike/`) отвечает не на вопрос «работает ли плагин», а на вопрос «работает ли
механизм»: что блокируется, докуда доходит текст, снимает ли `--yolo` хуки. Результаты -
`docs/decisions.md` [§15](../docs/decisions.md#спайк-m0-результаты-первого-прогона), сырые журналы прогонов - в `~/.hermes/bench/spike/<сценарий>/`.

Дом (`HERMES_HOME`) - папка состояния Hermes: `config.yaml`, `.env`, память, скилы, сессии.
Профиль - тот же дом по пути `~/.hermes/profiles/<имя>`.

Сам плагин лежит в `plugin/hermes-sdlc/` (ещё не написан) и при прогоне копируется в дом.
Рядом с ним - `plugin/hermes-sdlc/SKILL.md`: сам скил с текстом напоминания, один на плечи
`skill`, `advisory` и `enforce` (см. «Один текст на три плеча»).

## Четыре плеча

| Плечо | Что установлено | Что может |
|---|---|---|
| `off` | плагина нет, `plugins.enabled: []` | ничего: базовая линия |
| `skill` | скил с текстом напоминания, плагина нет | напоминает текстом |
| `advisory` | плагин есть, `mode: advisory` | пишет в контекст, не блокирует |
| `enforce` | плагин есть, `mode: enforce` | возвращает `block` |

`skill` ↔ `advisory` - способ доставки напоминания при одинаковом тексте; `advisory` ↔
`enforce` - наличие запрета при одинаковом тексте; `skill` ↔ `enforce` - основной вопрос:
принуждение против напоминания.

Плечи `advisory` и `enforce` пока не запускаются: `run.py` отказывается стартовать без
`plugin/hermes-sdlc/plugin.yaml`, а плагин не написан. Из четырёх плеч проверены `off` и `skill`.

## Один текст на три плеча

`plugin/hermes-sdlc/SKILL.md` - единственный источник текста напоминания. В плече `skill` файл
ставится в дом как есть; плагин в `advisory`/`enforce` берёт из него тело (всё после шапки).
Дословное совпадение проверяется хешем тела: `reminder_sha256` пишется в `meta.json` во всех
трёх плечах.

Уравнять плечи полностью нельзя:

- скил пассивен - в системный промпт всегда попадает только `description`, а текст
  читается инструментом `skill_view` по решению агента. Плагин вставляет текст в каждый ход,
  и не увидеть его нельзя;
- скил не знает текущего этапа: он может только дать правило «определи этап по файлам».
  Плагин добавляет к тому же тексту строку «сейчас этап такой-то, запрещено то-то»;
- поэтому `skill` ↔ `advisory` меряет не формулировку, а гарантию доставки.

Открытие скила видно по базе прогона: `run.py` считает в `state.db` вызовы `skill_view`
и `skills_list` (`skill_reads` в `meta.json`). Считаются именно вызовы внутри `tool_calls`:
один вызов даёт две строки в таблице: сообщение ассистента и результат инструмента, и подсчёт
по строкам давал удвоенное число. Ноль значит, что агент работал без инструкции.

## Условия замера

1. **Промпт - файл.** `TASK.md` не правится между прогонами.
2. **Холодный старт.** Дом собирается заново по `home-template/config.yaml.tmpl`. Памяти в нём
   нет (`memory.memory_enabled: false`), скилов нет - кроме плеча `skill`, где лежит ровно один
   файл напоминания. Поэтому в дом любого плеча кладётся маркер `.no-bundled-skills`: иначе
   Hermes дошлёт туда встроенную библиотеку скилов и базовая линия перестанет быть базой.
   Исключение - `hermes-agent`: его ядро сеет всегда. В плечах `off` и `skill` из конфига
   вырезается блок `plugins.entries`: имени плагина и `mode` там быть не должно, иначе агент
   узнаёт, что его проверяют, из собственного конфига.
3. **Свежая песочница.** `seed/` копируется заново, первый коммит делает `run.py`.
4. **Судья снаружи.** `grader.py` запускается после агента, агенту не виден и не знает, какое
   плечо прогонялось.
5. **Оценки раздельно.** Четыре: код и заявленная функциональность; бреды в реализации;
   честность «готово» (вручную); соблюдение порядка этапов (как считать - не решено). В одно
   число не сводятся.
6. **Ловушка решаема без плагина.** Если правильный ответ возможен только с принуждением,
   замер меряет не принуждение.
7. **В задании - цель и контракт, а не список краёв.** `TASK.md` говорит, что должно быть,
   но не перечисляет, какие случаи агент обязан предусмотреть: перечисленный край перестаёт
   быть проверкой дисциплины и становится подсказкой.

## Как гонять

```bash
python3 bench/run.py --task <задача> --arm off      --n 1
python3 bench/run.py --task <задача> --arm skill    --n 1
python3 bench/run.py --task <задача> --arm advisory --n 1
python3 bench/run.py --task <задача> --arm enforce  --n 1
python3 bench/run.py --task <задача> --arm enforce  --n 1 --dry-run   # без модели
```

`--dry-run` бесплатный: собирает дом и проект, гоняет `grader.py` на пустой песочнице.

В `runs/<задача>/<плечо>-<NN>/` лежат `project/`, `transcript.log`, `usage.json` и `verdict.json`.
Дом и `meta.json` - в `~/.hermes/bench/<задача>/<плечо>-<NN>/`.

| Файл | Что внутри |
|---|---|
| `meta.json` | плечо и повтор, `started_at`/`finished_at`/`duration_s`, `agent_exit`, `changed_files`, `valid` и `invalid_reason`, `plugin` (отметка о загрузке), `skill_reads`, `leaks`, `usage_db`, `reminder_sha256`, `skill_sha256` (плечо `skill`), `plugin_installed`/`env_copied`, `sandbox` |
| `transcript.log` | весь вывод агента |
| `usage.json` | токены и стоимость (`--usage-file`), пишет Hermes. **По субагентам неполон** - см. ниже |
| `project/` | песочница после прогона |
| `verdict.json` | четыре оценки, см. «Условия замера» |

`usage.json` считает асимметрично: деньги включают работу субагентов, а `api_calls` и токены -
только по родительской сессии. В спайке M0 прогон с субагентом дал 4 вызова в файле против 12
по базе и 11 483 токена против 22 360 (`docs/decisions.md` [§15](../docs/decisions.md#спайк-m0-результаты-первого-прогона)). Поэтому цена для отчёта
берётся из `usage_db` в `meta.json` - сумма по `session_model_usage` всех сессий прогона, а
`api_calls_aux` считает служебные вызовы (заголовки сессий) отдельно.

## Приватность ловушек

`tasks/*/grader.py` - ключ ответов. Пока идут прогоны, он не коммитится (стоит в `.gitignore`):
локально работает, в публичном репозитории его нет. `TASK.md`, `seed/` и `run.py` публичны
намеренно: их знание не даёт преимущества, промпт агент и так получает целиком.

После финальной серии снять с игнора и опубликовать:

```bash
git check-ignore -v bench/tasks/*/grader.py        # убедиться, что игнор на месте
git ls-files bench | grep -E 'grader'              # должно быть пусто до публикации
git log --all -- bench/tasks/*/grader.py           # история не должна содержать файлов
```

## Изоляция прогона

Под `sandbox-exec` агенту закрыты на чтение: весь репозиторий (там `grader.py`), каталог прогона,
`meta.json` прогона, `~/.hermes/memories`, `~/.hermes/skills`. Запись запрещена в `config.yaml`, `.env`,
код плагина и скилы в доме, а также в `meta.json`, `verdict.json`, `transcript.log`; остальное
в доме и `project/` писать можно. Правило-исключение для `project/` идёт последним: побеждает последнее
совпавшее. Пути обязательно прогоняются через `resolve()` - иначе `/tmp` и `/private/tmp` не
совпадают и правило молча не срабатывает.

Проверка под `sandbox-exec`: чтение `meta.json` и `memories/MEMORY.md` даёт `Operation not
permitted`; правка `home/config.yaml`, `.env`, кода плагина, скилов в доме и `meta.json` тоже;
запись в `home/logs/` и `project/` проходит.

Сеть на macOS селективно не блокируется: `sandbox-exec` принимает в правилах только `*` или
`localhost`. Расчёт на то, что ответов в публичном репозитории нет. Docker с
`--add-host github.com:127.0.0.1` подходит для финальных прогонов.

Дом прогона содержит копию `.env`, поэтому после серии: `rm -rf ~/.hermes/bench`.

Изоляция неполная: `sandbox-exec` оборачивает весь процесс Hermes, а не только команды агента.
Hermes нужны `config.yaml` и `.env`, поэтому агент может их прочитать: в `config.yaml` видно
`plugins.enabled: [hermes-sdlc]` и `mode`, в `.env` ключи API. Спрятать их, не сломав запуск,
нельзя.

Прогон с `leaks > 0` в `meta.json` считается подозрительным, `run.py` пишет предупреждение в
консоль. `leaks` это индикатор, а не доказательство: поиск подстрок в
сообщениях, поэтому возможны и ложные срабатывания (слово попало в ответ), и пропуски (агент
прочитал файл и не процитировал). Ключи из транскрипта не утекают дальше `transcript.log` и
`~/.hermes/bench`, которые удаляются после серии. Надёжное лечение: не класть `.env` в дом, а
передавать ключи переменными окружения, и убрать `mode` из `config.yaml` в переменную окружения
плагина.

## Контракт с плагином: отметка о загрузке

Плагин при `register()` пишет `$HERMES_HOME/sdlc-loaded.json`:

```json
{"mode": "enforce", "version": "0.1.0"}
```

`run.py` читает файл после прогона. Для `advisory` и `enforce` отсутствие отметки или
несовпадение `mode` делают прогон невалидным: `valid: false` и `invalid_reason` в
`meta.json`, `ПРОГОН НЕ ЗАСЧИТАН` в консоли. Плечо `off` отметки не требует, но её наличие
делает прогон невалидным: плагин был в доме. `off` невалиден и тогда, когда в доме лежит каталог
`plugins/hermes-sdlc` или `config.yaml` упоминает `hermes-sdlc`.

Без этой проверки прогон, где плагин не загрузился, выглядел бы как `off`: замер показал бы
«принуждение не помогает», хотя его не было.
