# МВП

**1 Плагин, который загружается и видит действия**
`~/.hermes/plugins/hermes-sdlc/` с `plugin.yaml` и `register(ctx)`. Хук
`pre_tool_call`, который логирует каждое действие и отвечает `{"action": "block"}`
на запрещённое.

**2 Четыре этапа и запреты**
Интервью → архитектура → код → сверка. Таблица запретов из `decisions.md`, без строки тестов.
Переключение этапа - по появлению артефакта.

**3 Состояние в проекте, защищённое**
`.sdlc/state.json` (этап, масштаб, режим тестов, критерии с метками) и
`.sdlc/log.md` (журнал). Состояние подписано, ключ вне проекта. Подмена ловится.

**4 Один файл `design.md`**
Секции: функциональность, требования, архитектура, вопросы человеку. Потолок
длины по масштабу.

**5 Два режима**
Жёсткий и мягкий как два плеча эксперимента. Мягкое плечо - тот же процесс,
описанный скилом, без хука. Режим тестов не реализуется.

**6 Один инструмент: `sdlc_check_dependency`**
Проверка допущения запуском (есть ли пакет, отвечает ли API). Результат в факты.

**6а Защита от обхода**
Белый список команд терминала: на этапах с запретом записи всё, что не в списке,
блокируется. Проверка при каждом действии, что `.sdlc/` не тронут.

**7 Одна задача-ловушка**
"Пропуск проектирования": простая песочница (30-40 строк), задача формулируется
так, что соблазн сразу писать код велик. Прогон в двух режимах.

**8 Скрипт прогона**
`run.sh`: поднимает Hermes с нужным профилем, отправляет промпт, сохраняет
транскрипт в `runs/`. Без него нет повторяемости.

**8а Метрика цены**
`post_api_request` получает поле `usage` на каждый запрос к модели, плагин
суммирует токены и пишет в состояние. `post_tool_call` считает итерации.

**9 Итоговый отчёт**
`.sdlc/reports/` со сверкой критериев, незакрытыми пунктами, допущениями и
числом итераций. Сверка идёт по наличию секций `design.md` и путям изменённых
файлов, без прогона тестов.

## Не входит

- Четыре ловушки из пяти
- Бенчмарки
- Отдельная сессия для критика
- Вопросы человеку с вариантами и строкой «не делать»
- Потолки длины `design.md`
- Режим с тестами: этап тестов, тестовый гейт, обработка flaky
- Машина состояний с инвалидацией артефактов

## Что считается успехом МВП

Один прогон, в котором агент пытается писать код до архитектуры, получает блок,
пишет `design.md` и только потом код. И второй прогон в мягком режиме, где он
этого не делает. Разница между ними и есть первое доказательство, что механизм
работает.
